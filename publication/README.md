# `publication/` — supporting documentation for the paper

Everything in this folder exists to be cited, checked or reproduced by someone
who did not build the graph. It is separate from `docs/`, which is the working
record for the team.

| | `docs/` | `publication/` |
|---|---|---|
| audience | the three of us | reviewers, and us in six months |
| contents | roadmap, decisions, findings, progress | claims, the evidence under each, and the scripts that regenerate it |
| changes | continuously | only with a re-run |

The registries stay single-sourced: **findings live in `docs/FINDINGS.md`,
decisions in `docs/DECISIONS.md`, experiments in `docs/EXPERIMENTS.md`.** This
folder references them by ID rather than copying them, so there is never a second
version of a finding to drift.

---

## Layout

```
publication/
  README.md                     this file — the claim → evidence index
  QUALITY_NOVELTY_RELEVANCE_REPORT.md   quality verdict, novelty-vs-literature check, downstream-module fitness
  APPLICATION_POSITIONING.md    the four real-world applications, what v1.0 supports, and the claim boundary (D-034)
  SOURCE_LICENCE_INVENTORY.md   every input traced to its origin evidence and licence status (D-036)
  GAP_ANALYSIS.md               what is wrong or naive about graph v1, measured
  ATTRIBUTE_ROADMAP.md          what to add, what to refuse, with validation plans
  evidence/
    E-300_attribute_audit/      attribute provenance + enrichment audit
      run.py                    regenerates every number in GAP_ANALYSIS.md
      result.txt                captured console output of the last run
      report.json               machine-readable summary
      granularity.csv           per-attribute observation granularity
      length_pairs.csv          per-pair chord vs along-track distance
      length_offset_bands.csv   projection collapse by offset band
      corridor_sinuosity.csv    corridor sinuosity ranking (871 corridors)
      bridge_validation.csv     GIS bridge capture vs official count, per zone
  figures/                      paper figures, regenerated by `make figures` (g06)
```

**Rule:** no number appears in a `publication/` document unless a script in
`evidence/` produces it. If a number cannot be regenerated, it does not go in the
paper. This is the same rule the project applies to the dataset.

| Component | Evidence | State |
|---|---|---|

than discovered by a reviewer: 42.9% of corridor–station incidences did not
resolve, and 24.5% of route km sits on edges carrying the defect signature.

capture rate (0.316, severely zone-biased) and the national route-km
reconciliation (`F-019`), which `E-102` showed was two zone-level errors
cancelling rather than a correct construction. Both belong in the paper. A
validation section containing only successes is not a validation section.

## Reproducing

```bash
pip install -r requirements.txt
python publication/evidence/E-300_attribute_audit/run.py
```

Requires the Phase 1 GIS source (`01_data_engineering/Railway_Network_.csv`),
the Phase 2 shipped dataset (`02_graph_inputs/graph_dataset/`), the graph v1
exports (`03_graph_construction/graph_v1/`) and `reference_data/`.

Runtime ~40 s, dominated by parsing the 119,446-row GIS table.
